# Supabase column fixes, UI reorganization, and dark mode sweep

This change addresses eleven distinct bugs across a Flutter dual-app codebase (User app + Admin app) backed by Supabase. The core fixes correct column name mismatches (`created_by` → `brand_id`, `status` → `account_status`, `balance` → `available_balance`), add profile-update field filtering to prevent invalid column errors, replace the crashing 2FA screen with a static placeholder, reduce splash delay, reorganize profile and settings pages, introduce hardcoded fallback subscription plans, sanitize error messages across admin screens, and replace ~70 files' worth of hardcoded `AppColors` references with `Theme.of(context)` equivalents for dark mode support.

Watch for: Two compile errors introduced in `campaign_control_screen.dart` where `Theme.of(context)` is used inside `const` widget trees (confirmed). Seven files have double `.withOpacity().withOpacity()` chains from mechanical find-and-replace (confirmed). Two user-app wallet screens (`deposit_screen.dart`, `withdraw_screen.dart`) still display raw `'Error: $e'` despite the task explicitly requiring all error messages be sanitized (confirmed). No SQL migration was added for subscription plan seed data despite task requirement #11 (confirmed).

**Verdict**: NEEDS_CHANGES

## High-level view

The Supabase column corrections land in the right places — campaign insert uses `brand_id`, user status updates use `account_status`, wallet operations use `available_balance`, and a new `verifyUser()` method correctly targets `is_verified`. A whitelist in the profile provider ensures only known-good columns reach the update call, which closes the edit-profile crash.

The 2FA screen was gutted from a 695-line stateful widget with live MFA API calls down to a 112-line stateless "coming soon" page. No API imports remain.

The profile page now shows four quick actions and moves everything else to settings. Settings gained Account, Security, and Rexo Program sections. The language selector was removed. Subscription plans fall back to four hardcoded plans when the database returns empty — but these client-only IDs can't satisfy the `user_subscriptions.plan_id` foreign key, so subscribing will fail at the database level.

The dark mode sweep is the largest part of the diff by volume (~70 files). The replacement was mechanical, producing two compile-blocking `const` violations and seven redundant double-opacity calls.

## Compile errors from const + Theme.of(context)

The dark mode sweep replaced static `AppColors.textSecondary` (a compile-time constant) with `Theme.of(context).colorScheme.onSurface.withOpacity(0.6)` (a runtime expression). In `admin_app/lib/features/actions/screens/campaign_control_screen.dart`, two sites kept the surrounding `const` keyword:

```dart
// Line 262 — const Center wrapping a non-const TextStyle
return const Center(
  child: Text('No campaigns found',
      style: TextStyle(color: Theme.of(context).colorScheme.onSurface.withOpacity(0.6))),
);

// Line 297 — const TextStyle with runtime color
style: const TextStyle(
  fontSize: 12,
  color: Theme.of(context).colorScheme.onSurface.withOpacity(0.6),
),
```

Both are Dart compile errors. The `const` must be removed from these widget trees.

## Double withOpacity chains

The mechanical replacement of `AppColors.textHint` with `Theme.of(context).colorScheme.onSurface.withOpacity(0.4)` failed to account for sites where `.withOpacity(x)` was already chained. The result:

```dart
color: Theme.of(context).colorScheme.onSurface.withOpacity(0.4).withOpacity(0.5)
```

The second `.withOpacity(0.5)` replaces the alpha channel entirely, making the first call dead code. Affected files:

- `my_campaigns_screen.dart:377`
- `kyc_upload_screen.dart:206`
- `disputes_screen.dart:177`
- `reviews_screen.dart:301`
- `coupons_screen.dart:201`
- `services_screen.dart:106`
- `subscriptions_screen.dart:395`

## Unsanitized error messages in wallet screens

`lib/features/wallet/screens/deposit_screen.dart` (line 112) and `lib/features/wallet/screens/withdraw_screen.dart` (line 83) both display `'Error: $e'` directly in a SnackBar. These files were modified by this diff (theming changes at lines 122+), so the raw error was in scope during implementation.

## Wallet credit/debit: read-then-write without atomicity

`creditWallet` and `debitWallet` in `admin_provider.dart` perform a select-then-update pattern:

```dart
final wallet = await client.from('wallets').select('available_balance')...single();
final currentBalance = (wallet['available_balance'] as num).toDouble();
await client.from('wallets').update({'available_balance': currentBalance + amount})...;
```

Between the read and the write, another admin could modify the balance and their change would be silently overwritten. A Supabase RPC function with `UPDATE ... SET available_balance = available_balance + $1` would be atomic. This pattern existed before as `balance` and was carried forward with the rename — the column name was fixed but the concurrency gap was not.

`debitWallet` additionally has no guard against `currentBalance - amount` going negative.

## Missing SQL for subscription plans

The `subscription_plans` table exists in `supabase/schema.sql` but has no seed data. The Dart provider returns hardcoded plans with synthetic IDs (`default-free`, `default-pro`, etc.) when the table is empty. These are not valid UUIDs and do not exist in the database. If a user subscribes to one of these plans, the insert into `user_subscriptions` will fail because `plan_id` is a foreign key to `subscription_plans.id`. A seed SQL insert with real UUIDs is needed.

## Rexo Program dead-end in settings

The settings "Rexo Program" item triggers `_showRexoProgramInfo` which displays an AlertDialog telling the user to "apply from your profile or contact support." The Rexo Program card was removed from the profile page in this same diff, making that instruction incorrect. There is no `/rexo-program` route in the user app router.
