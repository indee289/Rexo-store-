# RLS INSERT policies for user/wallet auto-provisioning

Third and final review pass. The single blocking issue from v2 — missing INSERT RLS policies on `users` and `wallets` — is resolved by `supabase/migrations/021_add_insert_policies.sql`. The migration adds INSERT policies gated on `auth.uid()::text` matching the row's owner column for `users`, `wallets`, `creator_profiles`, and `brand_profiles`, and adds SELECT/UPDATE policies for `notifications` (which had RLS enabled but no policies at all). The five Kotlin-side fixes from v1 remain intact.

Watch for: The `::text` cast in the INSERT policies is inconsistent with migration 020's direct UUID comparison style (`auth.uid() = id`) — functionally correct due to PostgreSQL's implicit casting, but may cause index bypass on large tables (possible). The `deposits` DTO still uses `brand_id` as the field name while the actual schema column is `user_id`, which will cause the deposit INSERT to write to a non-existent column (confirmed, but pre-existing — not introduced in this diff).

**Verdict**: APPROVED

## High-level view

The INSERT policies in migration 021 close the auto-provisioning gap. New users signing up will now successfully upsert their own row into `users` and `wallets` because the WITH CHECK clause permits inserts where the authenticated user's ID matches the row being created. The `creator_profiles` and `brand_profiles` INSERT policies are a forward-looking addition — the app doesn't currently create these rows client-side, but having the policies ready prevents the same class of failure if that code is added later.

The notification policies (SELECT and UPDATE on `notifications` gated by `auth.uid()::text = user_id`) fill a gap where migration 020 enabled RLS on the table but defined zero policies, making notifications completely inaccessible.

## `::text` cast vs direct UUID comparison

Migration 020 consistently uses direct UUID comparison:

```sql
-- Migration 020 style:
CREATE POLICY "Users can read own data" ON users FOR SELECT USING (auth.uid() = id);
CREATE POLICY "Users can view own wallet" ON wallets FOR SELECT USING (auth.uid() = user_id);
```

Migration 021 introduces a `::text` cast:

```sql
-- Migration 021 style:
CREATE POLICY "Users can insert own profile" ON users FOR INSERT WITH CHECK (auth.uid()::text = id);
```

`auth.uid()` returns UUID. The `users.id` column is also UUID. Casting one side to text forces PostgreSQL to cast the other side implicitly for comparison. In practice, INSERT policy evaluation happens once per row insert so index usage isn't relevant here — the concern is stylistic consistency across the migration set.
