# Phase 3 production fixes: table names, nullable DTOs, error sanitization, UI cleanup

This change addresses critical runtime crashes in the Rexo marketplace app: wrong Supabase table names (`store_products`/`store_orders` → `products`/`orders`), non-nullable DTO fields crashing on JSON null values, and raw Supabase error strings being shown to users. It also removes the Services bottom nav tab (leaving 4 tabs), strips the WelcomeCard and QuickStatsRow from HomeScreen, adds a DataStore-backed PreferencesManager for theme/language persistence, wires theme switching through MainActivity, adds `updateProfile()` to UserRepository with an EditProfileDialog on the ProfileScreen, and makes Profile settings items navigate to the full SettingsScreen.

Watch for: `updateProfile()` silently swallows all exceptions and provides no diagnostic signal to callers (confirmed); the `PreferencesManager` is accessed via a `lateinit` companion property on `RexoApplication`, which will crash if any code path accesses it before `Application.onCreate()` — unlikely in normal flow but possible during content provider initialization or instrumentation tests (likely); the SettingsScreen hardcodes "English" in the Language settings item on ProfileScreen regardless of the actual stored preference (confirmed).

**Verdict**: APPROVED

## High-level view

The table-name and nullable-DTO fixes eliminate the two most common runtime crashes. Every `store_products` and `store_orders` reference is corrected across both repositories, and all DTOs that can carry database nulls now declare `String?` with defaults of `null`.

Error sanitization is centralized in `ErrorUtils.sanitizeErrorMessage()` — a keyword-based classifier that maps failure categories (network, auth, schema, JSON, permissions) to user-facing copy. The catch-all strips URLs and API keys before deciding whether the residual message is safe to show. All four ViewModels route errors through it.

Theme persistence works end-to-end: DataStore → Flow → `collectAsState` in MainActivity → `darkTheme` parameter. Language persistence is stored but never applied — no `AppCompatDelegate.setApplicationLocales()` or `Configuration` change exists, so the locale never actually switches.

The UI topology removes the Services tab and hero card/stats row, adds an EditProfileDialog that writes name/handle/bio to Supabase, and routes Profile settings items to the full SettingsScreen. The `trailingText` labels on Profile's settings items are hardcoded strings rather than reading from DataStore.

<summary>Issues (5)</summary>

1. **updateProfile swallows exceptions** — `UserRepository.updateProfile()` catches all exceptions and returns `false` with no logging or error detail. Callers cannot distinguish network failure from permission denial. Add at minimum a logged exception or return a `Result<Unit>` that carries the sanitized message.
2. **Language preference stored but not applied** — `PreferencesManager.setLanguage()` writes to DataStore, but nothing reads it to call `AppCompatDelegate.setApplicationLocales()` or update `Configuration`. The setting persists but the app locale never changes.
3. **ProfileScreen SettingsList shows hardcoded "English" and "System"** — The `trailingText` for Language and Theme items in the `SettingsList` composable are string literals, not derived from the DataStore flow. Users see stale labels after changing preferences.
4. **PreferencesManager lateinit access window** — `RexoApplication.preferencesManager` is `lateinit` on the companion object. If a content provider or test runner accesses it before `Application.onCreate()`, the app crashes with `UninitializedPropertyAccessException`. Consider lazy initialization or a `nullable + requireNotNull` guard.
5. **updateProfile cannot clear fields** — Passing `null` means "don't update this field" (the `?.let` guard skips it). There is no way for a user to explicitly clear their bio or handle back to empty — an empty string passed by the dialog is converted to `null` via `ifBlank { null }`, which skips the update entirely.

## ErrorUtils broad keyword match

The "connect" keyword in the network-error branch is broad — any exception message containing the substring "connect" (including "reconnect", "disconnect", or even a success message mentioning "connected") would be classified as a network error and shown as "Network error. Please check your internet connection." In practice, Supabase client exceptions are unlikely to trigger this falsely, but the utility will misclassify if reused beyond its current call sites.

## EditProfileDialog field-clearing semantics

The dialog converts blank strings to null (`name.ifBlank { null }`), and `updateProfile` skips null entries via `?.let`. A user who clears their bio and taps Save will see no change — the bio remains whatever it was. To support clearing a field, the update map should include the key with an empty string (or use a sentinel), and the DTO should distinguish "not provided" from "set to empty".

The error path catches all exceptions and returns `false`. The dialog shows a fixed "Failed to update profile" message. If the Supabase RLS policy rejects the update, the failure is indistinguishable from a network timeout — no diagnostic information reaches the user or the developer.

## Dead ServicesScreen route

The `BottomNavItem.Services` object is removed from the nav bar, but `Screen.Services` and its NavGraph composable registration still exist. The route is unreachable from the bottom nav but remains in the nav graph — no immediate harm, but dead code that should be cleaned up.

## Hardcoded trailingText in ProfileScreen SettingsList

```kotlin
SettingsItem(
    icon = Icons.Outlined.Language,
    label = "Language",
    trailingText = "English",  // hardcoded, should read from DataStore
    onClick = onNavigateToSettings
)
```

After a user selects Hindi in SettingsScreen, the Profile page still shows "English" next to the Language item. The same applies to Theme showing "System" regardless of the stored value.
